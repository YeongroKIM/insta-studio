# 시그니처 포맷 1 (개정): "이렇게 요청하세요" 릴스

> 2026-11-17 CEO 피드백: 손그림 선 방식(`sketch-reel.md`)은 레퍼런스와 형식이 거의 같아 **보류**.
> 대신 **"이런 밋밋한 ○○을 → 이렇게 꾸미려면 업체에 어떻게 요청해야 할까요?"** 로 간다.

## 1. 핵심
결과 사진이 아니라 **업체에 그대로 보여줄 수 있는 요청 문구**가 주인공.
- 타깃(고르기 어렵고 용어를 모르는 예비신부)의 진짜 막힘 = "뭐라고 말해야 할지 모름"
- 브랜드 약속 "고민은 제가 할게요, 이것만 하세요"와 일치
- 저장 이유가 명확: **견적 받을 때 이 화면을 보여주면 됨**

## 2. 구성 (9:16, 약 13초) — 합성기 `ask` 모드
| 시간 | 화면 | 문구 |
|---|---|---|
| 0~2.2초 | BEFORE: 한국 아파트 기본형 | "이런 밋밋한 ○○을" |
| 2.2~3.2초 | 세로 막대가 쓸고 지나가며 AFTER로 | — |
| 3.2~5.2초 | AFTER (느린 줌) | "이렇게 꾸미려면?" |
| 5.2초~ | 화면이 어두워지며 **요청 체크리스트** 카드, 한 줄씩 체크 | "업체에 이렇게 요청하세요 👇" + 3~4줄 |
| 끝 | ⚠️ 주의점 1줄 + "🌰 저장해두고 견적 받을 때 보여주세요" | — |

## 3. 요청 문구 쓰는 법
- **업체가 알아듣는 말 + 쉬운 말** 같이: "가로로 긴 '니치'로" — 용어는 따옴표로 한 번만
- 한 줄 = 요청 하나. 3~4줄
- **공정·타이밍** 한 줄 넣기 (예: "배선 위치는 목공 마감 전에") — 지식 DB `10-interior` 근거
- ⚠️ 줄은 반드시 지식 DB의 주의점/전제조건에서 (예: "콘크리트 벽은 못 파요 → 가벽·실측")
- 지식 DB에 없는 수치(색온도·치수·가격)는 넣지 않는다

## 4. 캡션 템플릿
```
이런 밋밋한 [공간], 이렇게 바꾸고 싶다면 업체에 이렇게 말하세요 👇
① …
② …
③ …
⚠️ [주의점]
견적 받을 때 이 릴스 그대로 보여주세요. 도토리처럼 저장 🌰
#신혼집인테리어 #인테리어견적 #예비신부 #신혼집 #어쩌다신부
```
→ 캡션에도 요청 문구를 텍스트로 넣어 **복사해 갈 수 있게** 한다.

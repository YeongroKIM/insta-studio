# 지식 DB (knowledge)

결혼 준비 **생태계 지식**을 런칭 전부터 계속 쌓는 곳. 정보형 게시물의 원천이자, 나중에 자동 콘텐츠 생성의 학습 자료다.
관리: **09 지식관리자** Agent (`agents/09-knowledge.md`).

## 두 갈래 원천

| | 🐿️ 경험형 게시물 | 📚 정보형 게시물 |
|---|---|---|
| 원천 | `records/` (우리 기록) | `knowledge/` (이 DB) |
| 핵심 | "저는 이렇게 했어요" (회고·실패담) | "이 업계는 이렇게 돌아가요" (구조·비용·함정) |
| 신상 | 가장 엄격 (시차 2주+, 단서 조합 주의) | 낮음 (우리 이야기가 아님) |
| 검증 | 사실 그대로 | **출처 2곳 이상 + 기준일** |
| 자동화 | 어려움 (경험은 우리만 가진 것) | 쉬움 (DB가 쌓일수록) |

**가장 강한 게시물 = 정보형 뼈대 + 경험 한 줄** ("스드메 추가금 7가지 — 저는 3번에서 당했어요").

## 도메인 파일 형식

`domains/_template.md`를 복사해서 쓴다. 각 항목(사실)마다 **출처·확인일·신뢰도**를 단다.

- 신뢰도: `A` 공식(정부·기관·업체 공시) / `B` 다수 출처 일치 / `C` 단일 출처·후기 (게시물엔 "~라는 후기가 많아요"로만)
- **유통기한**: 가격·제도·규정은 확인일로부터 6개월이 지나면 ⏰ 표시, 게시 전 재확인
- 우리 경험에서 나온 사실은 출처를 `기록 YYYY-MM-DD`로 적되, 신상 단서는 빼고 일반화해서 적는다

## 원칙
- **베끼지 않는다.** 블로그·기사 문장을 옮기지 말고 사실만 우리 말로 요약, 출처 링크는 남긴다
- 업체 실명은 DB에도 쓰지 않는다 (구조·유형으로만: "청담 A샵" ✕ → "청담권 드레스샵" ○)
- 확인 안 된 수치는 넣지 않는다. 모르면 "확인 필요"
- 유료·로그인 전용 자료는 긁어오지 않는다
